# 素のbun run devも救う自動チェックインをv1に含める

人間の手癖(bun run dev)は矯正しきれない前提に立ち、デーモンがlsofでLISTENポートを定期スキャンして、既知のリポジトリ配下をcwdに持つプロセスを自動で台帳に登録し名前を広告する。yadoを経由しない起動も台帳に載るため、名前アクセスとLAN共有が付き、Ownerベースの調停が起動経路に左右されなくなる。

自動チェックインされたGuestには、名前とプロキシ経由のアクセスだけを提供する。ポートの自動割当とログのteeは、yado経由で起動した場合にのみ付く。HMR用WebSocketなど1プロセス複数LISTENの判別は、デーモン側のHTTP応答確認で行う。

## Considered Options

- PATHシム(bun/npmを上書き):完全に透過だがコアツールの上書きは侵襲的で、不具合時の切り分けが難しくなるため見送り
- プレフィックス方式のみ:実装は最小だが、素の起動が台帳から漏れ続け、干渉解消が運用任せになるため不採用
