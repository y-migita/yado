# 素のbun run devも救う自動チェックインをv1に含める

人間の筋肉記憶(bun run dev)を矯正しきれない前提に立ち、デーモンがlsofでLISTENポートを定期スキャンして、既知のリポジトリ配下をcwdに持つプロセスを自動で台帳に登録し名前を広告する。yado経由でない起動でも名前アクセスとLAN共有が付き、台帳から漏れる主体がいなくなるため、Ownerベースの調停が全Guestに効く。

自動チェックインされたGuestに提供されるのは名前とプロキシ経由アクセスのみで、ポート自動割当とログのteeはyado経由起動のときだけ。HMR用WebSocketなど1プロセス複数LISTENの判別はデーモン側のヒューリスティック(HTTP応答確認)で行う。

## Considered Options

- PATHシム(bun/npmを上書き): 完全に透過だがコアツールの上書きは侵襲的で、不具合時の切り分けが難しくなるため見送り
- プレフィックス方式のみ: 実装は最小だが、素の起動が台帳から漏れ続け、干渉解消が運用任せになるため不採用
