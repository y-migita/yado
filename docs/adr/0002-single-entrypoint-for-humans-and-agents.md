# 人間もエージェントも同じ入口(yado CLI)を使う

解決したい干渉問題(エージェント同士のポート衝突、エージェントがユーザーの起動したサーバーを巻き込む事故)は、起動経路が複数あると台帳から漏れる主体が生まれて解決できない。そこで「空きポート取得→mDNS登録→起動→台帳記録」を常に同じ`yado`コマンドに通す設計とする。ユーザーが生の`bun run dev`を叩くのをやめて`yado`を使うことが前提になる、という運用コストを受け入れる。

起動は引数なしの`yado`を基本形とし、package.jsonのdevスクリプトとパッケージマネージャ(bun/npm/pnpm)を自動判別する。例外は`yado -- <任意コマンド>`で明示する。CLAUDE.mdへの指示が「起動はyadoを使う」の一行で済むことを、自動検出の誤爆リスクより優先した。
